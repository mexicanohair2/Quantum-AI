# Материалы DeepSeek по Quantum-AI — перенос из истории проекта

**Назначение:** сохранить в репозитории все технические сведения о реализации Quantum-AI, которые удалось достоверно восстановить из доступного контекста предыдущих сообщений.

**Ограничение источника:** история содержит упоминания больших фрагментов кода и отчётов, но сами полные листинги файлов не доступны здесь как извлекаемые исходные файлы. Поэтому этот документ — точная сводка известных решений и проверочных замечаний, а не подмена отсутствующего исходного кода. Никакой модуль ниже не считается реализованным только потому, что он описан.

## 2. Токенизатор: зафиксированные ID

- Special token IDs: **0–4**.
- Byte token IDs: **5–260**.
- Начальный ID BPE-слияний: **261**.
- Для байта ASCII `a` (десятичное значение 97) ожидаемый token ID: **102** (`97 + 5`).
- Первое обсуждавшееся слияние пары `a a` должно ссылаться на `(102, 102)`, а не на `(97, 97)`.
- Следующее BPE-слияние должно учитывать ранее созданный token ID **261**, а не использовать 256.

Полный словарь merges и точная таблица специальных токенов не восстановлены.

## 3. Архитектура модели

В контексте описывалась реализация на PyTorch:
- Transformer decoder с причинной (causal) маской.
- RMSNorm.
- Grouped-Query Attention (GQA).
- SwiGLU feed-forward блок.
- `torch.nn.functional.scaled_dot_product_attention(..., is_causal=True)`.
- Embeddings и сохранение/загрузка checkpoint.

Не восстановлены: полный исходный код, конфигурация слоёв, число параметров, размеры hidden/head, RoPE-параметры, инициализация, точные форматы checkpoint и совместимость версий.

## 4. Генерация

Упоминались top-k и top-p sampling, repetition penalty, потоковая выдача токенов и инкрементальное декодирование UTF-8. Пороговые значения и точные алгоритмы обработки EOS/stop sequences не подтверждены.

## 5. Обучение

Упоминались train loop, scheduler, checkpoint и возобновление обучения (resume). В контексте встречались имена `latest.pt` и `backup.pt`, но файлы весов не доступны в этом переносе.

До появления исходников и логов нельзя утверждать, что обучение реально запускалось, checkpoint успешно сохранялся, loss сходился, модель выполняет inference или обучение завершилось.

## 6. Память и изоляция пользователей

Описывалась SQLite-память. Важное требование — каждый запрос к пользовательским данным должен ограничиваться `user_id` (например, условием вида `WHERE user_id = ?`). Упоминались embeddings, формируемые с помощью модели. Полная схема БД, миграции, политика удаления, транзакции и конкурентный доступ не восстановлены.

## 7. Reasoning и безопасность исполнения

Упоминался AST-парсер с whitelist разрешённых операций и математических функций. Это ограниченный вычислительный модуль, а не безопасный способ исполнять произвольный Python.

При восстановлении нужно проверить, что разрешены только явно перечисленные AST-узлы, запрещены произвольные функции/атрибуты/импорты, ограничены глубина и размер выражения, а ошибки обрабатываются предсказуемо.

## 8. Поиск и SSRF

Упоминался веб-поиск через HTML-страницы DuckDuckGo и проверки IP/DNS для снижения SSRF-риска.

В предыдущем аудите отмечено: тест DNS pinning был недостаточно строгим. При реализации необходимо проверять фактический адрес соединения, повторные DNS-разрешения, редиректы и запрет loopback/private/link-local/reserved адресов. Нельзя считать SSRF-защиту подтверждённой без тестов на DNS rebinding и redirect chains.

## 9. Vision

Упоминалась экспериментальная схема: CNN извлекает признаки изображения; формируются spatial tokens; projection приводит признаки к размерности языковой модели; cross-attention соединяет визуальные признаки с текстовым контекстом.

Не подтверждены обученные веса, датасет, preprocessing, поддерживаемые разрешения и реальный image inference.

## 10. Замечания к тестам из предыдущего аудита

1. **Byte IDs:** ASCII `a` должен иметь ID 102, поскольку byte ID = byte value + 5.
2. **Первый BPE merge:** пара `(102, 102)`, не `(97, 97)`.
3. **Следующий merge:** должен ссылаться на созданный ID 261, а не на 256.
4. **DNS pinning:** проверка должна учитывать фактический IP соединения, редиректы и повторное DNS-разрешение.
5. **Scheduler state:** сравнение состояния должно быть рекурсивным и корректно обрабатывать Tensor, dict и list.
6. **Memory concurrency:** ранее предложенный тест мог зависнуть из-за deadlock; нужны таймауты, корректное закрытие соединений и проверка завершения потоков.

Это замечания для повторной проверки, а не отчёт о пройденных тестах.
