# Quantum-AI — архитектура и статус

**Обновлено:** 22 ноября 2026 года  
Назначение: встроенный ИИ-помощник QQCross вместо энциклопедии.

## 1. Принцип продукта

Игрок использует существующий аккаунт QQCross с подтверждённой почтой. Quantum-AI не создаёт отдельную регистрацию.

Модель должна сама выбирать:
- ответить напрямую на основе устойчивых знаний;
- вызвать `web_search`, если нужны свежие или проверяемые сведения;
- изучить результаты, сопоставить источники и написать единый ответ в текущем чате.

## 2. Клиент

- `index.html` — минимальный интерфейс чата.
- `src/app.js` — история диалогов, отправка сообщений, обработка ошибок.
- `styles.css` — адаптивный тёмный интерфейс.
- История хранится в localStorage браузера.
- Клиент ожидает `POST /api/chat` с `{ messages: [...] }` и ответ `{ reply, sources }`.
- В публичный клиент нельзя помещать секреты провайдера.
- Пока сервер не развернут, `CHAT_API_URL` остаётся пустым и интерфейс честно сообщает, что ответы недоступны.

## 3. Серверная реализация

Файлы:
- `worker/index.mjs` — Cloudflare Worker, обработка чата, CORS, проверка сообщений, вызовы модели и веб-поиска.
- `wrangler.toml` — отдельная конфигурация Worker `quantum-ai-chat-api`, AI binding и публичные параметры Supabase.
- `tests/worker-smoke.mjs` — тесты прямого ответа, tool-calling, источников, CORS и дневного лимита.

Кандидат модели: `@cf/zai-org/glm-4.7-flash`. Документация Cloudflare указывает многоязычный диалог и function calling. Модель вызывается через `env.AI.run()`; ключ API провайдера не нужен.

Серверный цикл:
1. Проверить origin, размер запроса и структуру истории.
2. Передать модели историю и описание `web_search` с режимом `tool_choice: auto`.
3. Если модель не запросила поиск — вернуть её ответ.
4. Если модель запросила поиск — выполнить один проверенный запрос, передать результаты модели вторым вызовом.
5. Вернуть итоговый текст и ссылки на использованные результаты.
6. Не писать содержимое переписки в логи.

Ограничения:
- До 8 последних сообщений и ограничение их общего размера.
- Один вызов поиска на одно сообщение.
- До 4 результатов поиска с ограниченными фрагментами.
- Ограничение генерации ответа.
- Supabase ведёт независимый дневной баланс 10 000 нейронов для каждого подтверждённого игрока, с атомарными резервами и списанием.

## 4. Расход и ограничения Cloudflare

Cloudflare Workers AI предоставляет общую квоту 10 000 Neurons в сутки на аккаунт. На Workers Free после исчерпания квоты операции прекращаются; на Workers Paid превышение может тарифицироваться.

Лимит 10 000 нейронов на игрока — внутренняя квота QQCross, а не отдельная бесплатная квота Cloudflare. Если много игроков используют свои лимиты, общий расход Cloudflare может превысить бесплатную квоту.

Попытка чтения Billing Profile и подписок через текущую Cloudflare OAuth-интеграцию завершилась 403: у OAuth-сессии нет Billing Read scope. В аккаунте найден отдельный legacy Worker `qq-ai-cloud-api` с AI binding и usage model `standard`. Это ресурс QQ-AI: его запрещено изменять, переиспользовать или подключать к Quantum-AI. До подтверждения тарифа и общей статистики новый Worker не развертывать и не включать inference.

## 5. Поиск

- Внутренний инструмент: `web_search`.
- Модель вызывает его только при необходимости.
- Поиск не запускается для каждого сообщения.
- Сырая выдача не показывается пользователю вместо ответа.
- В итоговом сообщении отображаются ссылки на источники.

## 6. Проверки

Автоматические проверки в GitHub Actions:
- синтаксис клиентского и серверного JavaScript;
- отсутствие регрессий минимального интерфейса;
- прямой ответ модели через тестовую заглушку;
- вызов поиска по решению модели и синтез ответа;
- CORS, ошибки и дневной резерв;
- сохранение истории и мобильный UI.

До релиза отдельно проверить живой endpoint, реальные ответы Workers AI, реальный keyless-поиск и опубликованную страницу на Android.
