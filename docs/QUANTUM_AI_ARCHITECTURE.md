# Quantum-AI — архитектура и статус

**Обновлено:** 22 ноября 2026 года  
**Целевая архитектура:** единый онлайн-ассистент с инструментами, которыми управляет модель.

## 1. Принцип продукта

Quantum-AI — это один ИИ-ассистент, а не отдельный чат и отдельный поисковик. Пользователь формулирует задачу обычным языком. Модель решает, отвечать ли напрямую или вызвать инструмент. Внешний поиск является инструментом модели, а не самостоятельным пользовательским режимом.

## 2. Поток запроса

1. Клиент отправляет историю диалога и новое сообщение на защищённый серверный inference endpoint.
2. Модель анализирует запрос и самостоятельно выбирает один из вариантов:
   - ответить напрямую;
   - вызвать `web_search`, если нужны актуальные/проверяемые сведения;
   - после изучения результатов сформировать итоговый ответ.
3. Сервер выполняет только разрешённые вызовы инструментов и возвращает результаты модели.
4. Модель синтезирует материалы, отделяет факты от неопределённости и добавляет ссылки на использованные источники.
5. Весь результат показывается в той же переписке.

Поиск не должен запускаться на каждый запрос. Он нужен для свежих, изменчивых или требующих внешней проверки сведений. Обычные знания, объяснения и творческие задачи не требуют автоматического веб-поиска.

## 3. Инструмент web_search

- Tool name: `web_search`.
- Schema и executor находятся в `src/assistant-tools.js`.
- Поисковый провайдер вызывается только через executor инструмента.
- Результаты возвращаются модели в структурированном виде: title, url, snippet, publishedDate.
- Модель должна оценить релевантность и согласованность источников, а не копировать выдачу.
- В итоговом сообщении отображаются источники, на которые реально опирался ответ.
- Поиск зависит от индекса провайдера и не охватывает буквально весь интернет.

## 4. Клиент и приватность

- Один чат-интерфейс; отдельной вкладки/страницы поиска нет.
- История диалогов хранится в localStorage текущего браузера и не синхронизируется между устройствами.
- Секреты и ключи провайдеров запрещено помещать в публичный JavaScript.
- Сведения об использованных сторонних компонентах и лицензиях сохраняются в технической документации.

## 5. Текущее ограничение — inference backend

- Удалённая модель и автоматический цикл tool-calling пока не подключены.
- Наличие tool schema и executor само по себе не делает приложение работающим ИИ.
- Поэтому поле отправки сообщений остаётся выключенным до подключения и тестирования inference endpoint.
- Цель «без оплаты, без пользовательских ключей и без серверных расходов» ограничивает выбор хостинга. Нельзя обещать стабильный бесплатный inference без подтверждённого провайдера и его лимитов.
- Нельзя подменять реальный inference имитацией ответа или показывать результаты поиска как будто модель их проанализировала.

## 6. Проверки перед релизом

1. Проверить, что отдельного поискового экрана больше нет.
2. Проверить tool schema и executor на валидных, пустых и ошибочных аргументах.
3. Подключить удалённую модель, подтвердить её tool-calling и корректное продолжение ответа после результатов поиска.
4. Проверить цитирование, конфликтующие источники, устаревшие страницы, нулевые результаты и лимиты провайдера.
5. Выполнить end-to-end тест опубликованного сайта на Android.
