# Quantum-AI — архитектура и статус

**Обновлено:** 23 ноября 2026 года  
Назначение: встроенный ИИ-помощник QQCross вместо энциклопедии.

## 1. Принцип продукта

Игрок использует существующий аккаунт QQCross с подтверждённой почтой. Quantum-AI не создаёт отдельную регистрацию.

Модель должна сама выбирать:
- ответить напрямую на основе устойчивых знаний;
- вызвать `web_search`, если нужны свежие или проверяемые сведения;
- изучить результаты, сопоставить источники и написать единый ответ в текущем чате.

## 2. Клиент

- Основной интерфейс расположен внутри QQCross: вкладка «ИИ» заменяет прежнюю энциклопедию.
- `quantum-ai-chat.js` и `quantum-ai-chat.css` в репозитории QQCross отвечают за чат, баланс, прикрепление изображения и обработку ошибок.
- Клиент использует существующий Supabase Auth access token и сверяет UUID с профилем игрока.
- История хранится в localStorage отдельно для каждого UUID; синхронизации между устройствами пока нет.
- Клиент ожидает `GET /api/balance` и `POST /api/chat`; секреты провайдера в браузер не помещаются.
- После входа в QQCross интерфейс проверяет `/health`, затем получает личный баланс через `/api/balance` и только после этого включает поле отправки.

## 3. Серверная реализация

Файлы:
- `worker/index.mjs` — Cloudflare Worker, обработка чата, CORS, проверка сообщений, вызовы модели и веб-поиска.
- `wrangler.toml` — отдельная конфигурация Worker `quantum-ai-chat-api`, AI binding и публичные параметры Supabase.
- `supabase/functions/qqcross-ai-neuron-quota/index.ts` в репозитории QQCross — JWT-защищённая Edge Function, которая выполняет операции с личной квотой.
- `tests/worker-smoke.mjs` — тесты прямого ответа, tool-calling, источников, восстановления после сбоя поиска, CORS и дневного лимита.

Маршрутизация моделей:
- Все сообщения — текст, изображения и синтез после веб-поиска — обрабатывает одна модель: `@cf/qwen/qwen3.8-27b`.
- Cloudflare указывает для Qwen 3.8 27B текстовую генерацию, vision, reasoning и function calling.
- Модель вызывается через `env.AI.run()`; ключ провайдера не нужен.
- Единые коэффициенты: 40 909 нейронов на 1 млн входных токенов и 290 909 нейронов на 1 млн выходных токенов.

Серверный цикл:
1. Проверить origin, размер запроса, подтверждённую сессию QQCross и структуру истории.
2. Если приложено изображение, проверить MIME/размер и добавить image data URI в multimodal content. Независимо от наличия изображения выбрать Qwen.
3. Зарезервировать нейроны по тарифам Qwen, истории и консервативной оценке изображения/возможного второго вызова.
4. Передать модели историю и описание `web_search` с режимом `tool_choice: auto`.
5. Если модель не запросила поиск — вернуть её ответ.
6. Если модель запросила поиск — выполнить один поиск, передать ограниченные результаты модели вторым вызовом и сформировать единый ответ.
7. Списать фактический расход по usage metadata, когда оно возвращается; иначе использовать резервную оценку.
8. Не писать содержимое переписки в логи.

Ограничения:
- До 8 последних сообщений и ограничение их общего размера.
- Один вызов поиска на одно сообщение.
- До 4 результатов поиска с ограниченными фрагментами.
- Все запросы Qwen: до 2 048 токенов генерации, `reasoning_effort: medium` и `temperature: 1.0`.
- Резерв рассчитывается по единым тарифам Qwen, с запасом на два вызова при возможном веб-поиске.
- Изображения ограничены типами JPG/PNG/WebP и размером data URI; клиент предварительно уменьшает изображение.
- Для изображения резервируется дополнительный запас входных токенов до вызова модели.
- Supabase ведёт независимый дневной баланс 10 000 нейронов для каждого подтверждённого игрока, с атомарными резервами и списанием.

## 4. Расход и ограничения Cloudflare

Cloudflare Workers AI предоставляет общую квоту 10 000 Neurons в сутки на аккаунт. На Workers Free после исчерпания квоты операции прекращаются; на Workers Paid превышение может тарифицироваться. Тариф Qwen выше прежнего GLM, поэтому старые коэффициенты расхода неприменимы.

Лимит 10 000 нейронов на игрока — внутренняя квота QQCross, а не отдельная бесплатная квота Cloudflare. Если много игроков используют свои лимиты, общий расход Cloudflare может превысить бесплатную квоту.

Подключённая Cloudflare OAuth-интеграция не имеет Billing Read: Billing Profile, account billing usage и subscriptions возвращают HTTP 403. OAuth не поддерживает эти endpoint; нужен API token с Billing Read. Такой токен не предоставлялся и не помещался в код. В аккаунте найден legacy Worker `qq-ai-cloud-api`; это ресурс отдельного QQ-AI, он не изменялся и не переиспользовался. Для Quantum-AI создан отдельный Worker `quantum-ai-chat-api` на `https://quantum-ai-chat-api.qq-ai-cloud.workers.dev`, с собственным AI binding и Supabase configuration. Workers.dev subdomain включён. Billing Read всё ещё недоступен, поэтому тариф аккаунта и использование других AI-ресурсов не подтверждены. Cloudflare публикует 10 000 бесплатных Neurons в сутки на весь аккаунт; превышение на Workers Paid тарифицируется. Одна реальная проверка Qwen из API вернула 323 для `17 × 19` и сообщила расход 94.6 Neurons. Не считать внутреннюю квоту игрока отдельной бесплатной квотой Cloudflare.

## 5. Поиск

- Внутренний инструмент: `web_search`.
- Модель вызывает его только при необходимости.
- Поиск не запускается для каждого сообщения.
- Сырая выдача не показывается пользователю вместо ответа.
- В итоговом сообщении отображаются ссылки на источники.

## 6. Проверки

Автоматические проверки в GitHub Actions:
- синтаксис клиентского и серверного JavaScript;
- отсутствие регрессий минимального интерфейса;
- прямой текстовый ответ модели через тестовую заглушку;
- использование Qwen для текстового ответа, вызова веб-поиска, синтеза результатов и анализа изображения;
- вызов поиска по решению модели и синтез ответа;
- CORS, ошибки и дневной резерв;
- сохранение истории и мобильный UI.

GitHub Actions run #108 после последнего изменения Quantum-AI завершился успешно: JavaScript syntax, static regression checks, assistant-tool tests, per-player quota/backend smoke tests и chat browser smoke test. Тестовые ответы CI подменяются заглушками и сами по себе не подтверждают реальную генерацию. Прямая генерация Qwen проверена отдельно реальным вызовом API. QQCross PR #110 объединён в `main`; Pages deployment run `45085068113` завершился успешно. Worker `quantum-ai-chat-api` опубликован, workers.dev subdomain включён.
